# 雀潮模式

在观鸟配置界面打开“雀潮模式”。对应 `bird_settings.json` 的 `global.sparrowTideMode`，默认关闭；不会改写玩家的普通生成数量设置。

## 第一版规则

- 只在主世界已加载的适宜生物群系内触发。村庄、农田等沿用殖群系统的聚居评分；有树木的开阔边缘可触发小型聚集。沙漠、海洋、雪地、沼泽和地下不触发。
- 按环境评分选择 12～18、18～26 或 24～36 只的目标，附近已有麻雀也计入。仅为雀潮波次提供额外容量：附近纳入种群统计的野生鸟合计最多 48，麻雀常规事件容量 40、硬上限 48，区域有效容量至少 96。其他物种继续使用原上限；全局附近上限或麻雀上限设为 0 仍然禁止雀潮生成。
- 每波计划 4～8 只，波次起始间隔 7～18 秒；一波内部也分散到多个 tick。鸟从集合点周围 20～45 格的不同方向到来，避开玩家近处和可见生成点。受地形、视线、预算或容量限制时，实际数量可以少于目标。
- 聚集阶段最多 70 秒，之后活跃 3～8 分钟，不无限补鸟。晴天每隔 40～120 秒有 30% 概率尝试一次 20～40 格转场，始终留在原事件附近。
- 同区域及相邻区域受冷却保护，且检查事件半径是否重叠。成功事件结束后冷却 8～15 分钟；每维度最多同时控制两场事件。
- 清晨触发倍率 1.25，傍晚 1.35；雨天减半，雷暴和 13000～23999 时段不新增波次。已有鸟仍会优先寻找栖息与遮雨位置。
- 每只鸟最多关注 12 个伙伴；惊飞在邻鸟间延迟传播。大型群体减少单鸟叫声，并继续经过已有鸟群声音限流。
- 鸟粪完全沿用现有的个人冷却、区域冷却、数量上限和寿命规则，不因雀潮增加产量配置。

## 模式之间的关系

“雀潮”与愚人节模式独立；两者同时打开时，愚人节的体型及威胁规则仍按原设置生效。与殖群模式同时打开时，麻雀不叠加殖群扩群，其余鸟的殖群规则正常工作。刷怪蛋与繁殖数量没有改变。

模式关闭、玩家离开或事件结束时，只停止特殊聚集控制，绝不直接删除鸟。事件和冷却缓存仅保存在当前服务端会话中；重新加载世界后已有鸟按普通野生麻雀继续生活。

新增配置使用网络协议 17，客户端与服务器需要同时更新。旧配置缺少开关时默认关闭。

## 验证范围与实机检查

代码层定向检查覆盖昼夜与天气边界、环境分级、混合鸟种容量、已有麻雀抵扣、1000 次波次数量模拟、事件阶段、跨区域重叠、配置复制及网络往返。JSON 只检查本模式栖息地标签与中英文语言文件，并回归运行鸟粪区域限制测试。

仍需游戏内检查：

1. 在白天的平原村庄或麦田开启模式，等待低频随机事件，观察多方向到来、分波聚集及松散站位。测试玩家应正常观察或移动，生成点处于所有玩家视线内时波次会被跳过。
2. 使用生存模式冲入雀群，观察逐圈惊飞、飞行避障和再次落地；傍晚及雨天观察停栖与遮蔽选择。
3. 切换雷暴、夜间、自然生成开关或 `doMobSpawning`，确认不再增加波次；关闭雀潮后确认已有鸟不被删除。
4. 开启殖群与雀潮，确认不会叠乘；检查刷怪蛋仍一次一只、繁殖行为正常。
5. 多人从不同方向观察同一村庄，并在事件区域边界往返，检查没有重复扩群；观察大群的服务器耗时、叫声和鸟粪数量。

本次未运行 Gradle 或启动游戏，定向编译不等于完整打包或实机验证。
